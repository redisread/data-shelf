# data-shelf 产品设计

需求访谈已完成，第一版按下列已确认设计实现。

## 已确认

- 使用 mygo 开发 macOS 桌面应用，内容仅保存在本地，不考虑同步。
- 使用普通本地文件和真实嵌套文件夹组织资料，支持 Finder 查看、复制和备份。
- 新建文件和文件夹支持快速输入名字，不增加确认弹窗。
- 文件内容自动保存；合法 JSON 自动识别，格式错误或不完整的内容仍保留原文并提示错误；JSON 格式化为独立操作。
- JSON 和 Markdown 支持任意文本选区标记和一条可编辑评论，首版不加入多人回复或讨论串。
- 文件可继续编辑；修改后尽量保留标记关联，原文删除或无法可靠定位时显示为待重新定位，不猜测绑定。
- 首版目标为单文件 10 MB 内、总计数千份文件；超限明确提示，避免直接加载导致界面卡顿。
- Markdown 支持渲染；架构需允许后续扩展文件类型。

## 第二轮已确认

- 默认资料目录为 `~/Documents/data-shelf`，可更换；元数据保存在资料目录内，备份需包含隐藏目录 `.data-shelf`。
- 拖入和导入文件、文件夹时复制到资料目录，不更改来源；重名时拒绝覆盖。
- 显式扩展名优先；无扩展名且内容为合法 JSON 时补 `.json`。其他内容原样保存，可手动切换 Markdown 或普通文本。
- Markdown 提供源码、预览、分栏；在源码选区创建评论，预览支持常用 Markdown、表格、代码块和链接。
- 文件管理支持重命名、拖动移动、移到系统废纸篓、文件名筛选和当前文件内查找。
- 外部修改自动刷新；与未保存内容冲突时暂停自动保存，先生成本地副本，再加载外部原文。
- 左侧文件树、中间多标签编辑、右侧可收起评论栏；默认中文，跟随系统深浅色。
- 使用 mygo 原生 Go UI、原生代码编辑器和 Markdown 渲染器，不使用 WebView。

用户已确认以上设计并授权实现。后续文件类型通过格式识别和对应渲染器扩展；文件存储与评论模型不依赖 JSON 对象结构。
